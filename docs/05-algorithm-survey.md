# 握笔姿势检测：算法与模型深度调研（2026-09-27）

> 背景：当前方案（MediaPipe 2D 关键点 + 手工阈值）在真实写字视频上暴露了根本弱点：
> 笔挡住拇指/食指 → 关键点被"猜" → thumb_side 飞到 ±3（物理不可能），55% 时间窗不稳。
> 本文档调研学术界和工业界的做法，评估换/升级路线。

---

## 0. 结论（先看这个）

1. **当前方案处于文献里的最弱档位**。"手工特征 + 逐帧阈值"在所有已发表方案中
   准确率最低、鲁棒性最差；文献的主流是**学习式分类器**。
2. **立刻能做的升级（性价比最高）**：保留 MediaPipe 关键点，把"手工阈值"换成
   **时序分类器（LSTM/GBDT，30 帧 ≈ 1s 窗口）**。同类的关键点+LSTM 方案在手势任务上
   已发表 93~95%+ 准确率，且我们已算好的 15 个指标直接当特征用。
3. **中期最看好的方向**：**把手+笔一起建模**。PHHP 基准论文明确指出：
   握笔姿势的判别信息是"三根手指和笔的组合方式"，即**手-笔关系**——
   而我们现在的 15 个指标全部是**手内部**关系，一个都没用笔。
   "拇指捏在笔杆的哪一段、食指捏在哪一段"直接对应"拇指占笔过多"这个缺陷本身。
4. **别走的弯路**：MediaPipe 的 3D world landmarks 有已知崩溃 bug（手背朝向时塌缩，
   官方明确不修）——正好命中我们俯视看手背的场景；智能笔/智能手表路线准确率不高
   （72%）且要额外硬件；深度相机对笔记本不现实。

## 1. 候选路线对比

| 路线 | 代表工作 | 报告准确率 | 算力 | 数据需求 | 与本项目匹配度 |
|---|---|---|---|---|---|
| A. 手工特征+逐帧阈值（**现状**） | 本项目 | 合成手上可分，真实数据不稳 | CPU 极低 | 无 | ⭐ 已证明被遮挡噪声击穿 |

## 2. 关键证据

### 2.1 握笔姿势识别的专门研究（路线 C 的上界）

**PHHP 基准（IET Biometrics 2022，广东工业大学）**：
- 自建 18,000 张、9 类握笔手势（含 **wrap grip 包裹握法** = 我们要检测的拇指包食指），
  100 人、俯拍+侧拍两种视角、90% 复杂背景。**未公开下载**（Data availability: None）。
- 其 coarse-to-fine 网络测试集 95.3%（13M 模型）；ResNet34 94.1%；
  **MobileNetV3-large 93.7%（0.23 GFLOPs，笔记本 CPU 可实时）**。
- 论文点题：九类握法的差异是"三根手指与笔的 mix and match"，属于**细微特征**——
  这解释了我们手工指标为什么悬：关键点几何丢掉了笔和手指的接触外观。
- 中文硕士论文（7 类、自建 923 张）报告 82.16%——单类任务数据量小也能到 8 成。

**对本项目的换算**：我们要做的是**二分类**（正确 vs 拇指占笔过多/包食指），
比 9 类容易得多；但注意文献的样本都是"摆拍"握姿，写字连续帧更难。

### 2.2 关键点 + 时序分类（路线 B 的证据）

- MediaPipe 21 点 + LSTM（30 帧序列）：触摸绘图手势 >95%（IJVRA 2026），
  论文原话："简单阈值手势规则在真实场景经常失败，LSTM 显著更稳"。
- MediaPipe + CNN-LSTM（25 个动态词）：93.7%，模型仅 12.1MB，**CPU 上 35 FPS**
  （IEEE OTCON 2026）。
- 关键点序列 + Transformer（泰语手指拼写）：样本外 86.5%（更难的任务）。
- 共同结论：**时序窗口能"平均掉"逐帧噪声**——正对我们 55% 不稳窗口的问题；
  模型还能学到"不可靠段"的模式（等价于自动化的稳定性门控）。

### 2.3 为什么"笔"必须进特征（路线 D 的动机）

- 我们现有 15 个指标全部是**手内部**几何（拇指-食指、弯曲度、视角角），
  唯一与笔有关的信号是间接的（握着笔时手的形态）。
- PHHP 论文：判别信息 = 三指与笔的组合 → 笔杆上"三指各捏哪一段"就是分类依据。
- 用户描述的缺陷"**拇指捏的部位远大于食指，偶尔捏到食指上**"翻译成可测量特征就是：
  **拇指尖/食指尖在笔杆轴线上的投影位置与覆盖长度**。这比"拇指尖到食指的距离"
  （会被写字动作大幅扰动）稳定得多——笔杆位置在写字中相对手是缓变的。
- 笔检测在低技术成本上可行：孩子的笔是白/浅色长杆，用颜色分割+直线拟合
  （或 PCA 主轴）即可，CPU 开销可忽略；不必上深度模型。

### 2.4 3D 重建与 world landmarks 的坑

- **MediaPipe world_landmarks 已知 bug**：手背朝向相机时 3D 关键点整体塌缩
  （google-ai-edge/mediapipe issue #5156、#3994，官方答复"暂无修复计划"）。
  我们俯视看到的主要是**手背** → 路线"换 world landmarks 做 3D 几何"直接排除。
- **HaMeR（CVPR 2024，代码模型公开）**：ViT-based MANO 重建，对遮挡/截断/手-物交互
  鲁棒性显著优于 MediaPipe；但单帧 ViT 在 CPU 上秒级 → **只适合离线**：
  对录好的视频跑一遍，自动生成"大概率正确/错误"的预标注，人工只做确认，
  可把标注成本降一个量级。轻量替代候选（MobRecon/ACR，手机级实时 MANO）待验证。

### 2.5 工业界现状（对照组）

- 科大讯飞 T90 Pro、步步高 S10、作业帮等学习机：主打**坐姿/距离/歪头**监测
  （专用坐姿摄像头 + TOF），**没有一家把"手指级握笔检测"作为量产功能**。
- 解读：手指级检测在消费级产品里仍未被攻克/未产品化，侧面说明此问题难度；
  也说明我们不必对标"现成方案"，走 B+C+D 的组合就是前沿做法。

## 3. 与本项目实测问题的逐条对应

| 实测症状 | 根因 | 哪条路线解决 |
|---|---|---|
| thumb_side 飞到 ±3、55% 窗口不稳 | 遮挡→关键点被猜 | B（时序平均+学会丢弃不稳段） |
| 合成手阈值迁移到真实数据失败 | 手工特征不可迁移 | B/C（学习式，直接拟合真实分布） |
| 机位稍微偏一点指标就漂 | 2D 投影几何敏感 | D（笔杆相对手是缓变基准） |
| "拇指占笔多"没有对应指标 | 手内部指标不含笔 | D（笔杆投影特征） |
| 每帧独立判定、无记忆 | 无时序建模 | B（30 帧窗口） |

## 4. 分阶段实施计划

**阶段 0（已完成）**：真实数据体检（deep_scan）、稳定性门控、标定工具。
确认了"逐帧阈值"路线的天花板。

**阶段 1：关键点时序分类器（1~2 周，改动最小，先落地）**
- 数据：用窗口应用/`--camera` 录标注视频——正确握法 5s / 错误握法 5s 交替，
  3~5 轮，换位置换光照再来一轮；目标 **每类 ≥300 个稳定帧**（约 10 段视频）。
- 特征：现有 15 个指标（掌宽归一化，天然尺度无关）+ 新增 3 个笔杆特征（见阶段 2，
  可后补）+ 帧间速度。
- 模型：先用 **梯度提升树（LightGBM/sklearn GBM，窗口内统计量）** 打底，
  再上 **2 层 LSTM（30 帧 × 特征数）** 对比；sklearn/pytorch 均在现有 venv 可装。
- 验收标准：留出"换一天/换光照"的验证段，二分类 F1 ≥ 0.85，
  且误报率（正常被判错）≤ 5%/分钟（误报比漏报更伤使用意愿）。
- 产出物：`tools/train_cls.py` + `models/grip_cls.pkl`，窗口应用加载后替换现有阈值判定。

**阶段 2：笔杆特征（与阶段 1 并行，工作量小收益大）**
- 笔检测：HSV 分割浅色笔杆 → 形态学去噪 → 直线/主轴拟合 → 笔尖=下端点。
- 特征：拇指尖、食指尖在笔轴上的投影位置 t∈[0,1]（笔尖=0）、
  到笔轴的距离、"拇指覆盖段长度 − 食指覆盖段长度"。
- 这三个特征直接量化"拇指捏的部位远大于食指"，预期成为最强判据。

**阶段 3：手部图像分类器（阶段 1 不达标时升级）**
- 录样本时**同时存手部裁剪图**（窗口应用加一个开关，自动落盘），
  几百张即可微调 MobileNetV3-Small（迁移学习，CPU 训练可行）。
- 与阶段 1 分类器**集成投票**：关键点时序 + 图像 CNN 两路置信度融合。

**阶段 4（可选，标注加速）**：HaMeR 离线跑标注视频 → 自动预标注 → 人工纠错，
降低阶段 1/3 的标注成本。
