## 0. 这个项目的形状

用**桌面俯视/斜俯视机位**拍孩子写字的手，从手部关键点判断握笔形态，
不对就语音提醒一句。

- **独立进程**：一个崩了不影响另一个
- **独立摄像头**：**必须两颗**（坐姿要拍上半身，握笔要把手拍大，一个机位做不到）
- **复用设计结论，不复用代码**：相机封装、阈值建议、迟滞规则、语音播放这些
  在坐姿项目里验证过的做法照搬过来，但代码是复制而非 import ——
  否则这个仓库单独克隆下来就跑不起来（见 `pg_utils.py` 文件头的说明）

### 0.1 范围收窄（2026-09-26 用户决定）

用户明确了两件事，项目范围因此大幅收窄：

1. **固定一个检测角度：左侧**（不做多机位/多角度自适应）
2. **主要只纠正一个问题：大拇指包住食指**

这个收窄是好事，原因：

| | 收窄前 | 收窄后 |
|---|---|---|
| 问题类型 | 多类握法识别 | **二分类**（包 / 不包） |
| 机位 | 需要通用视角 | 固定一个角度，变量少一个 |
| 判据 | 要覆盖 6+ 种形态 | 只要一对指标 |
| 可行性 | 精度余量很紧 | 单点问题上余量宽松得多 |

判据（`docs` 里叫 `THUMB_OVER_INDEX_PAIR`）由两个指标合成：

```
thumb_side        拇指尖相对「食指根→小指根」横轴的偏移
                  偏正 = 越到食指外侧 = 疑似包住
thumb_index_dist  拇指尖到**食指折线**的最短距离
                  小 = 真的搭在食指上（而不是悬在旁边）
```

两个必须一起看：只看前者会把"拇指伸过食指尖"也算进来；
只看后者分不清搭在食指的哪一侧（正常捏笔时拇指也贴着食指）。

⚠️ **一个待你确认的关键点**：见 §2.0「左侧到底是哪一侧」——
**如果侧的选反了，拇指的遮挡会让这个错误根本看不见。**

## 1. 两个叫停点（先过这两关再写功能）

| | 问题 | 通过判据 | 不通过 |
|---|---|---|---|
| **第 0 关** | 看得见吗？摄像头能不能把手拍得够大、跟得够稳 | 手宽 **≥200px**、检出率 **≥90%** | 改机位/换相机；仍不行 → **停** |
| **第 1 关** | 分得开吗？指标能不能把"正确/错误握笔"分开 | 至少一个指标 **margin ≥ 1.5**，且最优阈值下误报漏报都很少 | → 按 §6 退回方案 E |

且误差最大的恰是判定最需要的 **PIP 关节**。
盲目往下写功能，很可能做出一个"永远不准或永远不叫"的东西。

## 1.1 机位是哪一侧（已定：右手写字，电脑在孩子左边、镜头朝右）

**这个必须先定下来，因为选错侧会让要抓的错误根本看不见** ——
不是"精度差一点"，是信息被手指遮掉了。

右手握笔、手背朝上放在桌上时，从上往下看：

```
        拇指   ← 靠身体中线的那一侧
   ┌─────────────┐
   │   右手背     │
   └─────────────┘
        小指   ← 靠外侧的那一侧
```

| 机位 | 看到什么 | 能不能判「包食指」 |
|---|---|---|
| **从拇指侧拍** | 拇指在最前面，**把食指挡住了** | ⚠️ 难 —— 而"有没有压过食指"恰恰要看食指 |
| 从小指侧拍 | 食指在前、拇指在后/上 | ✅ 拇指越过食指这件事看得见 |
| **从上方俯拍** | 拇指食指的左右关系一目了然 | ✅ **最好** |

### 用户的实际机位（2026-09-26 已确认）

**右手写字；电脑放在孩子左边、镜头朝右。**

对右手来说，这就是**从拇指那一侧平着看** —— 正好是上表里最难的那一格。
要看的食指会被拇指挡住。

#### 对策（按代价从低到高）

1. **先把摄像头抬高，以 45~60° 俯角往下看手**（最省事，通常就够了）
   俯视分量一加上，拇指和食指的**左右关系**就看得见了 ——
   平视会把横向信息压扁，斜俯视不会。
2. 抬高仍不行 → 把摄像头挪到孩子**右侧**（小指那一侧）
3. 再不行 → 按 §6 退回握笔器

#### 怎么判断行不行：看 `metric stability` 那一行

工具左边会实时显示：

| 显示 | 含义 | 该怎么办 |
|---|---|---|
| `metric stability: GOOD` | 姿势稳住时指标很稳（std 小） | 这个角度可用 |
| `FAIR` | 勉强 | 能录，但结论要打折扣 |
| `POOR!` | 指标在帧间乱跳 | **必须换角度再录** |

物理意义：**姿势没变却跳，就说明模型在猜被挡住的点**。
⚠️ 只看掌心抖动发现不了这个问题（手可能确实没动），所以要看**指标本身**的 std。

另外右下角的**「拇指-食指放大镜」**也可以直接肉眼看：
红圈是拇指尖，看它和食指的关键点有没有贴在手指上。

## 2. 第 1 关的实验协议

### 1.2 「测哪一只手」—— 实测踩到的坑

孩子写字时**左手也搭在桌面上**（不可能不放），所以画面里**总是有两只手**。

原来 `num_hands=1` 只回一只手，很可能就是那只**静止的左手** →
所有指标都算在错的手上，表现就是"总是误识别左手"。

**⚠️ MediaPipe 的 `handedness` 标签（Left/Right）不能用来解决这个问题** ——
它假设输入图像是**镜像的**（自拍视角）。外接摄像头是正像，
所以标签会**左右报反**。这正是"总是识别成左手"的直接来源。
（"换成用标签判断"是错的方向，只会把问题换个样子。）

**解决办法：按「画面位置」指定，完全不碰那个标签。**

| 方式 | 说明 |
|---|---|
| **手动锁定**（推荐） | 按 `[` 锁画面左半那只，`]` 锁右半那只。存进 `pen_grip_config.json`，下次沿用。机位固定时锁一次就行 |
| 自动 | 按运动量猜：写字的手一直在动，搭在桌上的基本不动 |
| 分不出来 | **拒绝记录**并提示锁定 —— 录到错的手上比没数据更糟 |

屏幕上会**同时画出两只手**：被测的画亮绿并标 `MEASURING`，另一只画灰并标
`ignored`；画面正中有一条分界线（锁定的依据）。handedness 标签只显示出来做参考，
并明确标注 `UNRELIABLE`。

### 1.3 一个好消息：判据不关心左右手

判据是**手部内禀**的（全部由关键点之间的相对关系算出）：

```
across     = normalize(小指根 - 食指根)
thumb_side = dot(拇指尖 - 食指根, across)
```

镜像时两个向量都翻转 x，点积里的 x·x 项不变 —— **结果完全一致**。
离线自检 `B2` 专门锁这条（把整只手翻转 x，所有指标必须一模一样）。

所以：**孩子用左手还是右手，判据不用改、正负方向也不用翻。**
唯一的变量就是"别选错手"，见 §1.2。

## 2. 第 1 关的实验协议

工具：`python hand_probe.py --camera 0`

### 步骤

1. 摆机位：**桌面斜上方俯视手部**，距离 30~60cm，让手占画面主体
2. 看画面左侧 `view:`，必须是 **OK**（不是 MARGINAL/BAD）
3. 让孩子分别摆三种握法，每种按对应键 **各录 5~10 帧**
4. **关键：每种握法要换 3 个位置/角度各录一遍**（画面中央、偏左、偏右）
   —— 只在一个位置录的数据会给出虚假的高可分性
5. 按 `p` 看对照表

### 结果怎么读

| 看到什么 | 含义 | 下一步 |
|---|---|---|
| 某指标 `✅ 分得开`(margin≥1.5)，扫描后误报漏报都 ≤1 条 | 有希望 | 进 §3 阶段 2 |
| 只有 `⚠️ 勉强`(0.8~1.5) | 边界情况 | 多录一轮（换光照/角度）再判；或考虑多指标组合 |
| 全部 `❌ 重叠`(<0.8) | 关键点分辨不了 | 多录一轮确认 → 按 §6 退回 |
| 换了位置后 margin 大幅下降 | **伪可分**：模型在认位置不是在认握法 | 以换位置后的低值为准 |

### 一个必须警惕的陷阱

合成手自检里 `拇指食指间距` 的 margin 高达 **134**，
但那是**人造数据**、类别差异是我自己写进去的 —— 真实数据绝不可能这么好。
**这些数字一律不能当结论。**

## 3. 里程碑路线

### 阶段 1：验证（当前）
- 第 0 关 + 第 1 关实测
- 产出：一份真实的对照表

### 阶段 2：最小可用判定（通过第 1 关后）
- 只用**实测分得开的指标**，其余全部删掉（不做"万一有用"的保留）
- 加多帧确认：连续 N 帧判为错误才触发（复用 `ReminderGate` 的迟滞思路）
- 仍然**不加界面**，先用命令行跑一周，看误报

### 阶段 3：提醒与界面（误报率达标后）
- 复用 `posture_engine` 的线程化引擎 + 快照模式
- 复用 `Speaker`（独立线程 + 深度1队列 + wav）
- 复用 `ReminderGate`（迟滞 + 两道间隔：同类 90s、任意 30s）
- 复用 `ReviewStore` 的审核存图思路做阈值标定
- PySide6 界面：手部特写 + 状态卡片（沿用"不用红色、手绘表情"的设计）

### 阶段 4（可能不做）：笔的检测
"握得太低""笔杆角度"这两项**必须定位笔**才能测（专利 CN114399786A 走的就是
"笔尖投影点 + 笔杆顶点"算夹角）。需要自定义训练数据和标注，是另一个量级的工作。
**除非阶段 2~3 效果明显不够，否则不做。**

## 4. 指标清单（候选，不是判据）

| 指标 | 含义 | 假设方向 | 实测结果 |
|---|---|---|---|
| `fist` | 四指平均弯曲度 | 越小越像拳头 | ⏳ |
| `curl_index` | 食指弯曲度 | 拳握时变小 | ⏳ |
| `tip_close` | 指尖到掌心的平均距离 | 拳握时变小 | ⏳ |
| `spread` | 相邻指尖张开度 | 越挤越小 | ⏳ |
| `thumb_index_gap` | 拇指尖↔食指尖距离 | 偏大可能没捏住笔 | ⏳ |
| **`thumb_side`** | **拇指横向越过食指的量** | **偏正 = 拇指包住食指** | ⏳ |
| `thumb_index_angle` | 拇指与食指在食指根处的夹角 | 偏小可能捏太紧 | ⏳ |

「假设方向」只是从解剖学直觉来的，**全部待实测**。

## 5. 已实现的设计约束（都是踩过坑换来的）

| # | 约束 | 理由 |
|---|---|---|
| 1 | 先转像素再算距离/角度 | MediaPipe 的 x/y 各自归一化，不转会被宽高比压扁。坐姿项目因此"侧面角度系统性漏报 44%" |
| 2 | 用掌宽做归一化基准 | 包围盒随手指张合变化，掌宽不随 → 指标不受远近和画内位置影响 |
| 3 | 只用 2D | MediaPipe 的 z 实测标准差是 x/y 的 1.5 倍以上 |
| 4 | 必须有视角门控 | 手太小/抖得厉害时不下结论。文献记录过连续约 4 秒完全丢失坐标 |
| 5 | 拒绝不合格样本 | 对照实验里，视角不合格时**拒绝记录**，避免污染结论 |
| 6 | 合成手只用于测试 | 它的可分性是人造的，绝不可当结论 |

回归锁（`tests/test_grip_offline.py`）里有一条特别设计的：
不仅验证"正确算法在旋转下不变"，还验证"**错误算法确实会漂移**" —— 否则这个锁是假的。

## 6. 退路：方案 E（握笔器）

如果两关没过，**不要硬做视觉方案**。握笔器 5~20 元、物理约束、成熟几十年、当天见效。

视觉方案可以做它的补充而不是替代：
- 握笔器负责**限制**（让错误握法握不住笔）
- 视觉方案若能被验证到"只做粗判且误报低"，才考虑做**抽查**

两条路不冲突，可以先用握笔器。
