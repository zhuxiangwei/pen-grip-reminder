## 2. 真正的病根：`palm_w` 会塌缩

把 512 帧按"掌宽是否正常"分成两组：

| 分组 | 帧数 | `palm_w` 中位 | `thumb_side` 标准差 |
|------|------|--------------|-------------------|
| 正常 | 108 | 79 | 0.289 |
| **异常** | **404** | **50** | **0.702** |

最极端的几帧：

```
帧548  px_w=137  palm_w=  8.3  thumb_side= +5.127   ← 手有 137px 宽，掌心只有 8px
帧355  px_w=108  palm_w= 12.3  thumb_side= -4.529
帧357  px_w=112  palm_w=  7.1  thumb_side= -4.304
```

**手明明有 137px 宽，掌心宽度却只剩 8px。** 物理上不可能 —— 这是
「手掌几乎侧对镜头」的几何塌缩。

### 2.1 为什么这会毁掉判据

`thumb_side` = 拇指相对食指的**横向**偏移 / 掌宽。

```
thumb_side = 横向偏移 / palm_w
```

`palm_w` 从 79 掉到 8，分母小了 10 倍，于是：
- 分子里**微小的定位抖动**被放大 10 倍 → `thumb_side` 冲到 ±4.5
- 而"拇指包食指"的真实差异量级只有 **~0.3**
- 结果：噪声 (±0.7 标准差) 比信号 (0.3) 还大 → **信噪比 0.21，判不出来**

`thumb_index_dist` 稍好（信噪比 1.20），因为它用点到折线距离、不吃侧向塌缩，
但 1.20 也远不够做阈值。

## 3. 几何推导：要多少俯角才够

手掌背面大致朝上。设镜头光轴与水平面夹角为 **θ（俯角）**，
则镜头看到的"手掌横向分量"只有 `sin θ`：

| 俯角 θ | 手掌视角角预期 | 横向分量保留 |
|--------|---------------|-------------|
| 0°（纯侧平视） | 90° | **0%** ← 完全判不出 |
| 30° | 60° | 50% |
| **37°（当前实测）** | **53° ← 和实测 58.5° 吻合** | **60%** |
| 45° | 45° | 71% |
| 60° | 30° | 87% |
| 70° | 20° | 94% |

推导结果和实测**对得上**（预测 53° vs 实测中位 58.5°），说明模型是对的：
**当前俯角约 37°，横向只剩 60%，再叠加手在画面里偏小，就崩了。**

> 📌 注意：`palm_view_angle` ≈ 90° 是"从正上方看"。
> 当前 58.5° 偏离 90° 有 31.5°，就等于俯角只有 ~37°（90-37=53）。

## 4. 怎么改（两个都要做，缺一不可）

### 4.1 把笔记本挪近 —— 解决"手太小"

目标：手宽从 131px 提到 **≥200px**，即**放大约 1.6 倍**。

- 当前手距离镜头估计 **~55–65cm**
- 要放大 1.6 倍 → 距离降到 **~35–40cm**
- 笔记本**侧面推到桌子中间**，紧挨着孩子写字的手（约一拃远）
- ⚠️ 别太近：镜头是定焦，**<20cm 会糊**；35–40cm 是甜点

### 4.2 把盖子往键盘方向压 —— 解决"角度太侧"

目标：俯角从 37° 提到 **≥60°**，即 `palm_view_angle` 从 58° 提到 **~75°+**。

- 盖子从 50-60° 压到 **离键盘 25-35°** 左右
- **屏幕会看不见，这是正常的** —— 所以配套用 `录制握笔.bat` 盲录（蜂鸣器计时）

> 两个是乘法关系：手放大 1.6 倍 × 横向分量从 60% 提到 87%，
> 整体判据质量提升约 **2.3 倍**，`thumb_side` 信噪比有望从 0.21 到 >1。
